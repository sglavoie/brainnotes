# Serving modes and capabilities

Companion to `CLAUDE.md`; read before adding a route that writes, launches a
process, or serves bytes out of the vault, and before branching on "is this
server local".

- **One table, not a flag.** `internal/web/capabilities.go` derives a `Mode` once, in `NewServer`, from the two mutually exclusive `Options` flags (`modeFor` refuses `--read-only` *and* `--hosted` together rather than picking one: a replica publishes a vault this process does not own, hosted publishes the vault itself, and silently resolving the pair would serve a deployment nobody asked for). `capabilitiesFor(mode)` then answers every later question. The capabilities are **independent dimensions**, which is the whole point of the table: hosted is not "read-only with writes turned back on". `documentWrites` covers note, property, configuration and sidecar mutations; `processLaunch` covers starting the configured editor or agent command; `browserOpen` makes an Open action answer with a route to navigate to instead of starting an editor; `maxRequestBody` is the transport bound. Local is `{writes, launch, 32 MiB}`; read-only is `{browserOpen, 1 MiB}`; hosted is `{writes, browserOpen, 1 MiB}`. A handler must ask `s.caps`, never re-derive a deployment from an option.
- **Where a refusal lives.** `requestGuard` is the single middleware every request passes through and refuses two classes before a handler runs: `denialReason` (read-only's route **allowlist** — a route not named in `replicaRequestAllowed` is unavailable until somebody reviews it — plus `processLaunchRoute` for a mode without `processLaunch`) and a cross-origin state change. `processLaunchRoute` names the five routes whose success starts a process and which have **no browser equivalent**: `/api/config/open`, `/api/brief/insight`, `/api/note/insight`, `/api/daily-review/agent`, `/api/synthesis/generate`. Three routes are deliberately absent — `/api/open`, `/api/brief/item` and `/api/related/item` — because they mean something without a process: with `browserOpen` they answer `{"ok":true,"destination":"/n/<key>"}` instead. Absent from *this* list is not the same as reachable: read-only's POST allowlist is exactly `/api/brief/view` and `/api/brief/item`, so it still refuses the other two with `read-only replica` and only hosted exercises all three navigating branches. Their boundary is a branch inside the handler, and the two panel actions share one door (`openNoteTarget`) rather than each growing their own, so a mode that cannot start an editor answers every Open with somewhere to go. Each has a test proving the navigating branch never reaches `openPath`.
- **The guard is not the guarantee.** Both process doors refuse again at the single point of exec: `openPath` raises `errProcessLaunchDisabled` and `launchAgent` raises `errAgentLaunchDisabled` before calling `runAgent`. That is belt and braces on purpose — the route list in `processLaunchRoute` is a list somebody can forget to extend, while the two doors are where a *request* ends in a **configured** command: an editor or an agent named in `brainnotes.local.toml`, run on a machine nobody is sitting at. That is the boundary, and it is narrower than "no subprocesses". A hosted write forks `git`: every journaled mutation goes through `noteops.BeginOperation` into `internal/vaultgit`, whose `gitExec` runs an executable resolved once at `Open` with argv the engine builds, and `initializeServeSafety` resolves that engine in exactly the modes with `documentWrites` — local and hosted. It is not gated on `processLaunch` and must not be: the Git safety engine is what makes a hosted write recoverable, and refusing it would publish a writable vault with its undo history switched off. When you read `agentAvailability` telling a hosted reader "this server does not launch processes", read it as the sentence a person needs about *their* configured command, not as a claim about the process table. The package builds one elsewhere: `openBrowser` in `browser.go` starts the local browser at startup, reachable from no route, and its one caller in `server_handlers.go` is gated on `caps.processLaunch` as well, so a library caller that builds `Options` by hand over a vault whose `[serve]` section enables the browser cannot spawn one on a machine nobody is sitting at. A new route that starts a *configured* command must go through `openPath` or `launchAgent`; do not add a third door for one.
- **Availability is a page-level answer, not just a route-level one.** `agentAvailability` is the one function a page asks before rendering an AI control, and it returns the explanation with the verdict because they are one decision: a mode without `processLaunch` reports the feature unavailable *and* must not tell a person to configure `[agent].command`, which would change nothing and would send them editing a file on the wrong machine. The caller supplies only the unconfigured wording, and this decides whether that is the true explanation. `briefAvailability` does the matching thing for the editor: with `browserOpen` the Open action navigates, so a configured editor is no longer a precondition for it.
- **Headers are a property of the deployment.** The guard sets `Cache-Control: private, no-store` on every response, because a hosted deployment sits behind a shared cache (Cloudflare, a corporate proxy) that must not retain a note it served to one authenticated person; `X-Content-Type-Options: nosniff`; `Referrer-Policy: same-origin`, so the `/n/<key>` someone is reading stays out of the `Referer` of every external link in that note; and `X-Frame-Options: DENY`, because the CSRF token is no defence against a click in a same-origin frame and a hosted deployment's write controls would otherwise be clickjackable. That is `X-Frame-Options` rather than a CSP `frame-ancestors` directive because `applyMediaSafetyHeaders` **`Set`s** its own `Content-Security-Policy` on an active attachment, and `Set` replaces: a guard-set CSP would be dropped on exactly the responses that most need a framing rule. `noCacheStatic` relaxes the blanket `no-store` for the one `/static/` prefix — the bundle holds no vault content, so it may be stored and revalidated — and repeats `private` rather than inheriting it, because `Set` replaces the header outright and the same bytes for everyone still must not become a shared-cache entry.
- **CSRF and origin are two checks, not one.** Every mutating route checks the per-process token — `csrfTokenMatches(s.csrfToken, requestCSRFToken(r))`, reading `X-BN-CSRF` or the `token` form field — after parsing its form and before any side effect. The agent and synthesis routes get there through `requireManagementPost`, which bundles the whole preamble (exact path, POST only, optional per-route body bound, `ParseForm`, token); the rest parse their own request shape and make the same call inline, so the token check is universal while the preamble around it is not. `sameOriginRequest` in the guard is defence in depth beside it, and it matters most in hosted mode where the server is no longer reachable only from loopback. It prefers `Sec-Fetch-Site` when the browser sends it, because the browser computes it and it survives a reverse proxy that rewrites `Host`, which an `Origin`/`Host` comparison does not; absent that header a present `Origin` must name this host; a request with **neither** header is not a browser request (curl, the CLI, a test) and is left to the token, which a cross-site page still cannot read. An opaque `null` origin — a sandboxed frame, a `file://` or `data:` document — parses to an empty host and is refused.
- **Body bounds belong to the profile, not the route.** A profile reachable from another machine is bounded at 1 MiB; local is bounded at 32 MiB, because a bulk action over a very large vault posts a real number of note keys and refusing it would be a regression rather than a defence. The guard refuses an over-declared `Content-Length` with an honest `413` and *still* wraps the body in `http.MaxBytesReader`, because a chunked request declares no length and a small declared length can still send more. `requireManagementPost` takes a per-route bound only for a route that needs to be **stricter** than its deployment; passing zero leaves the profile-wide bound in place. A few routes run the other way: a form-encoded payload is several times the size of the content in it, so `capabilities.requestBodyLimit` widens them wherever the profile's bound is narrower. `routeBodyLimit` is the whole list — `/api/synthesis/preview` at `synthesisPreviewBodyLimit`, `/api/source/preview`, `/api/source/save` and `/api/source/create` at `sourceRequestBodyLimit` (three times `noteops.MaxSourceBytes` plus room for the revision, the save id and the token), and `/api/attachments/upload` at `config.MaxAttachmentFileBytes` — the *ceiling* on what any vault may configure, which is why the body of that one request is the file raw with no form encoding to pay for. That does not make a request unbounded — each route applies that same bound itself a moment later in `requireManagementPost`, and `noteops` enforces the content limit on the decoded value — it makes the bound the route's instead of the profile's, so a hosted deployment can preview a full-size draft or save a full-size note rather than finding a feature capped by a number chosen as a defence. **Widen in `routeBodyLimit` and nowhere else**, and only for a route that re-applies the number: a widening the route does not re-apply is a profile bound removed rather than moved.
- **An attachment is arbitrary bytes from the same origin as the note pages.** `applyMediaSafetyHeaders` is the only place that decision is made. A passive type (image, audio, PDF) is served as declared. An **active** type — `text/html`, the script types, and anything with a `+xml` suffix, matched on the base type with parameters stripped, with an unparsable type treated as active because the safe answer for unclassifiable bytes is the restricted one — gets `Content-Security-Policy: sandbox` (opaque origin, scripting off, so a booby-trapped `.html` in the vault cannot read any other route) plus `Content-Disposition: attachment`. The sandbox is applied **only** to active types rather than to every response, because a restrictive policy on a directly navigated image breaks the synthetic image document browsers wrap it in. A type `http.DetectContentType` merely *guessed* is downgraded to `application/octet-stream`: a file whose name claims nothing and whose bytes look executable must not be run. The filename goes through `mime.FormatMediaType` rather than into the header by hand, so a name holding a quote, a semicolon or a newline cannot forge a header; a name that cannot be encoded at all is dropped while the bare `attachment` stays, because downloading is the property being defended. `privateMediaPath` refuses both configuration layers and every dot-path, checked against the **symlink-resolved** relative path as well as the requested one — which is also what makes upload staging unservable, since `.bnotes/uploads/` is a dot-path and therefore refused under its own name and through any link that resolves into it.
- **Read-only and hosted answer `/api/open` differently, and that is deliberate.** Read-only `403`s it, because its POST allowlist is exactly `/api/brief/view` and `/api/brief/item`; hosted answers with a destination. A replica exists to be a published copy with the narrowest possible surface, while a hosted vault is the real thing and its Open action has to mean something.
