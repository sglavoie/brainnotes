# Synthesis workbench internals

Companion to `CLAUDE.md`; read before changing any `/api/synthesis/*` route, the `/synthesize` page, or `internal/noteops/synthesis.go`.

The browser presents one sequence: select sources, prepare context, write a draft,
then review the exact note before creating it. Context is required by the preview
API even when Ask AI is not used. The optional generation control stays secondary
to the person's draft and never replaces it without an explicit action.
The next-step prompt explains that context enables preview while drafting remains
available. The context disclosure reports whether it is not prepared, ready, or
needs an update; its action is offered above the draft when the disclosure is closed.

- **Synthesis workbench request model**: `/synthesize?source=<note key>` (`internal/web/synthesis_page.go`) is a server-rendered shell that carries the anchor identity and destination default as `data-synthesize-*` attributes and is inert without JavaScript; it requires exactly one non-blank `source` key, so a missing, blank, or repeated key is a `400` rather than a silently-chosen anchor. `POST /api/synthesis/context` and `POST /api/synthesis/generate` (`internal/web/synthesis_api.go`) are a **read-only pair** — neither writes Markdown, recall state, the undo journal, nor any file — so they sit outside the write classes above entirely. A context request reloads configuration, resolves every route key against the current snapshot, ranks the chosen notes through `recall.Ranker.RankSelected`, and renders one `recall.BuildCuratedContextBundle` packet; the packet bytes, the ordered note identities, each note's `SourceHash()`, and the configuration's `Fingerprint().Composite` are held in the in-memory `synthesisContextStore` (`internal/web/synthesis_context.go`) under a `crypto/rand` identifier that expires after one hour. Lookup is **non-consuming** — a context is reusable so a retry costs nothing — which is why the store prunes on write rather than on read. Both synthesis stores are bounded and self-expiring: the context store holds at most `synthesisContextMaxRecords` (32) packets and `synthesisContextMaxBytes` (8 MiB) of packet bytes, evicting the record nearest expiry first, and `NewServer` starts a `synthesisSweepInterval` (one minute) background sweep that releases aged-out records with no later request and stops itself once the store is empty, so an abandoned tab's packet is not resident for the process's life. Eviction needs no new client path because an evicted context is the same `CodeNotFound` an expired one is; a record wider than the whole byte budget is still admitted once the store is empty, since refusing it would make the packet unreachable rather than merely short-lived. The clock is mutex-guarded and replaced only through `setNow`, because the sweeper reads it from its own goroutine. The user prompt is folded into `recall.ContextPurpose.Instructions` rather than carried beside the packet, so the stored bytes are self-contained and generation forwards them to the agent unchanged. Freshness is checked immediately before *and* after the command runs, against a forced `refreshSnapshot`: a note that moved, vanished, was quarantined, or whose bytes changed, and an edit to *either* configuration file, are all `CodeConflict` (409), while an unknown or expired `context_id` is `CodeNotFound` (404) because the browser's remedy is to rebuild rather than retry. The configuration digest is read from disk instead of reusing the published `ConfigStatus.SourceHash`, for two reasons: an edit that fails to validate leaves the last-good hash published and a packet built before that edit still has to be reported as stale, and `SourceHash` names the portable file alone while what the packet was built under is the pair. `synthesisConfigState` is the single read — it returns the composite *and* the per-file requirements from one `config.ReadSources`, because those are two different questions and the composite can only answer the first. **A composite digest is not a file state**: pinning it as one would expect a hash no file on disk holds, which is exactly the regression the split exists to prevent.
- **Synthesis write class**: `POST /api/synthesis/preview` and `POST /api/synthesis/apply` (`internal/web/synthesis_write_api.go`) are the preview-gated side of the file-write line, and all four synthesis routes share one transport prologue (`requireSynthesisPost`: exact path, POST only, bounded body, parsed form, CSRF). Preview looks its context up, revalidates it, calls `noteops.PlanSynthesisNote`, and stores the **plan itself** — not the request — in the in-memory `synthesisPreviewStore` (`internal/web/synthesis_preview_store.go`, five-minute TTL, far shorter than the context TTL because a receipt claims a destination is still free rather than describing research; bounded at 32 receipts and 8 MiB of planned note bytes with the same nearest-expiry eviction and background sweep as the context store, and an evicted receipt is the `preview_required` a replay already returns, so no file can be lost to it). Apply therefore accepts nothing but `preview_id`: title, folder, draft, and sources all come from the stored plan, so no request can substitute content the user never reviewed. The receipt is consumed (deleted under the store mutex) *before* any mutation, which is what makes a replay — including a concurrent one, and including a retry after a failed apply — return `preview_required` rather than a second note. A receipt does **not** need its context record to still be alive: the plan already pins every source revision, so a draft that outlived its packet still applies. Failure codes split by where the check ran: the web layer's own pre-commit revalidation (`verifySynthesisPreview` — configuration digest, every `plan.Requirements` path, and the destination's continued absence) is `preview_stale`, while anything the `vault.FileTxn` refuses at the commit boundary is `conflict`; both are HTTP 409, and only the transaction's recheck actually makes the write safe. The configuration is pinned twice on purpose — as transaction requirements, and as an explicit digest comparison — because a vault with no configuration file records no requirement and only the digest notices one appearing. The requirements are **per file**, carried on the context record as `ConfigRequires` and handed to `noteops.PlanSynthesisNote` verbatim: `brainnotes.toml` with `ExpectHash`, and `brainnotes.local.toml` with `ExpectHash` or `ExpectMissing`, so an overlay created between the preview and the commit is a conflict rather than a second source nothing read. Their paths are vault-relative because that is the form a `SynthesisRequirement` carries and `noteops` is what resolves and contains them. `s.state.invalidate()` runs only after a successful create, so a refusal never disturbs the snapshot. `Server.beforeSynthesisCommit` is a nil-in-production test seam that runs between revalidation and commit; it exists because the validation-to-commit race cannot otherwise be provoked deterministically.
- **Synthesis workbench frontend**: the `/synthesize` page is built entirely in the browser from focused modules rather than bolted onto the related/search controllers — `synthesize-model.ts` (state shape and formatting), `synthesize-sources.ts` (the selection algebra: add/remove/move/reorder/dedupe, each returning an `{ok, message}` outcome the controller announces), `synthesize-storage.ts` (versioned `localStorage`), `synthesize-requests.ts` (suggestion and search fetches), `api-synthesis.ts` (all four synthesis endpoints, exported through the `api` barrel, each refusing a response that does not answer the request it was sent), `synthesize-view-elements.ts`/`synthesize-view-sections.ts`/`synthesize-view-panels.ts`/`synthesize-view.ts` (the DOM builders and the `SynthesisView` they assemble into the template's empty mount), `synthesize-render.ts` (the update pass that rewrites that view from the model), and the controller split across `synthesize-runtime.ts` plus four action modules — `synthesize-selection.ts` (source add/remove/move/drag), `synthesize-discovery.ts` (suggestion tabs and vault search), `synthesize-context-actions.ts` (prepare/copy/generate and the candidate panel), and `synthesize-create-actions.ts` and `synthesize-write-actions.ts` (preview/apply/discard/restore) — wired together by `synthesize.ts`, with `fetch`/`storage`/`clipboard`/`confirm`/`redirect` injected for tests. `synthesize-runtime.ts` is why that split is possible: the model, the view, the in-flight flags the render pass reads, and the few operations more than one group performs live on one shared mutable `SynthesisRuntime` rather than in a closure only the controller could see. Persisted state (`SYNTHESIS_STORAGE_VERSION = 2`) holds **note keys, the text the user typed, and the generated candidate's Markdown only** — never source bodies, excerpts, the packet, or any rendered HTML — and identities are rehydrated on load through `GET /api/related?source=<key>&limit=1`, whose `404` is also how a note that left the vault is detected and warned about; that reuse is why restoring a selection needs no endpoint of its own. The candidate's `rendered_html` is deliberately not persisted, so a restored candidate is shown as Markdown rather than re-injected from storage. A stored entry that is not a string is discarded rather than coerced, because a coerced key resolves to nothing and would then report itself as a note the vault lost. Changing the sources, their order, the purpose, or the prompt invalidates `context_id`; editing the draft, title, or folder does not, because those never reach the packet — but all six invalidate an outstanding `preview_id`, because a receipt claims one specific set of bytes. Those same inputs stay editable while a request is in flight, so `prepareContext` and `preview` snapshot `synthesisContextSignature`/`synthesisPreviewSignature` before the `await` and drop the response — success *and* failure — when the model no longer matches: without that, a late success re-installs an artifact for values the user has replaced, and a late `not_found` failure calls `forgetContext` on a context that a newer request already rebuilt. The stale check therefore runs before `invalidateSynthesisPreview` and before the `not_found` branch, because an obsolete response must not report the current inputs as broken. Generated output never reaches `model.draft`: the candidate lives in its own panel behind Replace/Append/Copy/Dismiss, which is what makes a second generation, or a failed one, non-destructive. The agent disclosure is shown once per page load and gates the request itself, so declining sends nothing; its wording must describe the server's real retention — the prompt and the packet stay in `synthesisContextStore` memory until the context expires, is evicted to keep memory bounded, or the process restarts and are never written to disk, the stored packet reaches the configured command only after acceptance, and the generated candidate is not stored server-side at all — and that wording is pinned by both `internal/web/static_src/synthesize-generation.test.ts` and `docs/web-synthesis.md`. A `not_found` from generate or preview means the packet expired: the controller clears the context and the receipt, keeps every character the user wrote, and points at Prepare. Apply carries nothing but `preview_id` and guards duplicate submission with an `applying` flag set before the first `await`, since a disabled button alone would still lose a race with an already-queued click. Apply and Discard both delete the saved record through `clearSaved`, which counts an absent storage as already clear and a refused `removeItem` as a failure: neither then claims the saved work was cleared, and Apply withholds its redirect and offers a link to the created note instead, because navigating away is exactly what would hide the warning that the draft will reappear. Each async area keeps its own `role="status"` region next to the control it belongs to, matching every other page, but no message is ever written to two of them: selection outcomes go to the page-level `[data-synthesize-status]` and nowhere else, so a reorder is announced exactly once. The selected-source summary is deliberately *not* a live region — it restates what the move announcement already said, and would double-speak every reorder. Search snippets arrive server-escaped and are written with `innerHTML` (matching `search.ts`), while related excerpts are plain text and use `textContent`. Drag drop-targets are filtered to supporter rows, which is what keeps the anchor pinned at position 1 without a special case. The responsive half of the layout contract lives in `internal/web/static_synthesize_css_test.go` rather than a jsdom test, because jsdom has no layout engine and cannot evaluate a media query.
