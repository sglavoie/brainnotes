# Graph view internals

Companion to `CLAUDE.md`; read before changing the `/graph` page, `internal/web/graph.go`, or any `internal/web/static_src/graph*.ts` module.

- **The payload is a faithful directed graph and every reduction is client-side**: `internal/web/graph.go` emits one node per included note and one edge per resolved wikilink, with `filteredDegree`, `folder`, and `matchesQuery` already computed, and it is the *only* thing the server decides. Mutual-edge merging, neighborhood isolation, the minimum-degree floor, and folder collapse are all **display-only transforms over an already-fetched payload** — none of them has a server counterpart, none of them refetches, and none of them may ever grow one. That is what keeps the API answer cacheable and honest: two browsers looking at the same `/api/graph.json` see the same graph regardless of how their knobs are set, and a screenshot of a reduced view can always be explained as a projection of the full one. `mergeReciprocalGraphEdges` (`graph.ts`) is the one reduction that runs unconditionally, inside `normalizeGraphPayload`; the other three are the display pipeline below. Both call sites recompute degrees **before** the merge, because the merge halves each reciprocal pair and counting after it would undercount every mutual link. The merge is **idempotent by construction**: it carries an incoming `mutual` flag onto the surviving edge instead of recomputing it from scratch, because the second pass inside `buildDisplayGraph` sees an edge list where every reciprocal pair has *already* been collapsed to one line and so no longer looks reciprocal — a pass that reset the flag would silently un-flag every mutual edge in the graph (it did, until Session 7 fixed it). Collapse's parallel-edge dedupe carries it the same way: `mutual` describes the pair the line stands for, so a flagged duplicate folded onto an unflagged survivor promotes the survivor.
- **`g_*` params never reach `buildFilteredAPIURL`**: `g_isolate`, `g_mindeg`, and `g_collapse` (`graph-controller.ts`, `readPageDisplayParams`/`syncPageDisplayParams`) are display state, not filter state. They are read from and written to the URL through `updateBrowserQuery` alone, never through `publishFilterChange`, and `buildFilteredAPIURL` (`filters.ts`) copies only `sharedFilterParamKeys`/`queryShapeParamKeys` — so a knob change lands in a shareable URL without leaking into the fetch, and moving a slider structurally cannot cause a network request. Each param is omitted at its off value (`""`, `0`, `0`), so a default view keeps a clean URL — though "omitted" is a property of the *write*, not of the load: an incoming URL that spells an off value out (`g_mindeg=0`) keeps it until the next knob change triggers a write. `syncPageDisplayParams` writes **all three** on every call from one `GraphDisplayParams` record: a future knob must be added to that record and that write list, because a knob left out of it would be silently dropped from the URL by the next write from any other knob.
- **`g_hops` is retired, and compatibility is a client-side rewrite and nothing more**: the isolation radius was once a fourth param, and the whole of its migration is deletion. `canonicalizeLegacyDisplayParams` (`graph-controller.ts`) runs inside `initGraph` *before* `bindControls()`/`scheduleLoad`, so the address bar is clean before the first fetch; it uses `URLSearchParams.delete`, which removes **every** value under the key, so a doubled `g_hops=2&g_hops=3` leaves nothing behind, and `updateBrowserQuery` rebuilds the URL from the current pathname, the surviving parameters, and the current hash — unrelated query state and the fragment survive. `syncPageDisplayParams` deletes the key again on every write, so no path can put it back into a URL a user is about to share. The value is never *interpreted*: there is no clamp, no default, and no `hops` field anywhere in state, so a legacy link renders the same fixed one-hop neighborhood as a fresh one. Be precise about the scope of that promise — this is a `replaceState` in the page, so nothing server-side ever sees, rejects, or redirects `g_hops`; `internal/web/graph.go` and every route are untouched by the retirement, and a bookmark is only corrected once the page it points at has loaded.
- **The display pipeline's stage order is load-bearing**: `buildDisplayGraph` (`graph-controller-view.ts`) applies isolate → min-degree → collapse, in that fixed order, so the three knobs compose predictably no matter which order the user touched them in. Isolate takes exactly one *undirected* step out of the anchor over the pre-merge edge list — the anchor plus the notes linked to it in either direction, so an inbound-only neighbor is kept — and `isolateStage` takes no radius argument at all: there is no traversal left to bound, which is what stops a future caller from reintroducing one. Everything outside that neighborhood, and every edge touching it, is *removed* rather than dimmed, so it is absent from Cytoscape and can drive no tap, hover, selection, details, or keyboard behavior (`findDisplayedNodeModel`/`isDisplayedNodeID` are the only interactive lookups, and they resolve strictly from `state.displayGraphElements` with no source fallback). An anchor absent from the current source is a no-op returning `isolated: false`, not an empty graph. Min-degree is deliberately **one pass, not iterated to a fixed point** — dropping a hub's leaves can leave the hub displayed at degree 0, which is correct — and `keepIDs` (the selection and the isolate anchor) is exempt *at this stage only*, so collapse can still fold the anchor into an aggregate. Collapse groups by the first *N* path segments (`folderGroupKey`), turns any unexpanded group of two or more into one aggregate placed at its first member's list position, drops intra-group edges (which become self-edges under the remap) before any degree recompute, and dedupes remapped parallel edges — that dedupe runs only when collapse actually produces an aggregate, so display-graph edge uniqueness must not be assumed at depth 0. **Degrees and sizes are then recomputed from the displayed edge set, never carried over from the fetched one**, and the reciprocal merge re-runs last because collapse can turn two one-way note links into a reciprocal aggregate pair. An aggregate is sized from `memberIDs.length` rather than its surviving degree, so a 40-note folder cannot render smaller than a 5-link note (`nodeSizeForDegree` clamps at 16 members, so folder mass stops reading past that). An aggregate is identified by its `isAggregate` flag and never by the `folder:` id prefix — a note key may legitimately start with `folder:` — and it can never become the selection: tapping one toggles `expandedFolders` instead, which is what keeps "Isolate selection" and "Open note" meaning exactly one note.
- **`state.currentGraphElements` is the fetched source of truth; `state.displayGraphElements` is what is mounted**: which one a consumer reads is a correctness question, not a style one. The details/hover model resolves against the *displayed* set first so an aggregate reports the counts actually drawn, while the fetched set answers questions about the vault. `state.matchIDs` is likewise the fetched match set and must be projected through the aggregation into `displayedMatchIDs` before it can drive highlighting, zoom-to-matches, or that button's disabled state — an aggregate matches when any member does, and a collapsed group hiding a match must not be dimmed in focus mode. `elementSignature` is computed over the **displayed** elements and `rebuildDisplay` is its only writer, so `loadGraph`'s focus-mode fast path compares "what the new payload would mount" against "what is mounted": comparing payloads instead would let a knob change read as "nothing changed". `pruneExpandedFolders` runs in `loadGraph` *before* `buildDisplayGraph` for the same reason — the signature and the mounted graph must share one expansion set. Expansion is sticky-but-pruned across a refetch (a keystroke must not re-collapse a folder the user just opened) and cleared outright on a depth change, since the keys are depth-specific. When the pipeline reports `isolated: false` while an anchor is set, the anchor is dropped from state and from the URL with a status notice rather than letting the graph spring silently back to full.
- **The vendored layout chain must load in dependency order, and the controller degrades to `cose`**: `graph.html` loads `cytoscape.min.js` → `layout-base.min.js` → `cose-base.min.js` → `cytoscape-fcose.min.js` → `app.js`, all `defer`, and that order is behavior, not cosmetics — fcose is built on cose-base on layout-base and registers against the global Cytoscape factory. `TestServer_GraphPageIncludesAssets` (`internal/web/server_pages_test.go`) pins the whole chain by relative position. fcose does **not** self-register, so `cytoscape.use(window.cytoscapeFcose)` in `registerGraphLayouts` is mandatory; that function is deliberately tolerant of a missing extension *and* of a bare-function factory with no `.use`, and either case leaves `hasFcose()` false rather than throwing. `layoutOptionsForSpread` then returns `cose` options built from the same spread formulas, and `runLayout` calls `separateIsolatedNodes` **only** on that fallback path, because fcose's `tile: true` already parks zero-degree nodes and running both fights the layout. None of the fcose-only options (`quality`, `packComponents`, `tile`, `nodeSeparation`) exists in `@types/cytoscape`, so the fcose builder goes out through an `as unknown as` cast and `tsc` cannot check those four names — a typo in one of them is invisible to the compiler and to the tests.
- **Labels are culled in screen space, except in `all` mode**: `applyGraphVisualClasses` (`graph-controller-labels.ts`) runs `cullCollidingLabels` over the candidate set from `labelIDsForCurrentState`, testing each estimated label box against the boxes already accepted and seeding the accepted set from the selected and hovered nodes; `labelMode === "all"` bypasses the cull entirely, which is the escape hatch for "I know it overlaps, show me everything". The geometry is an estimate, not a measurement — `estimateLabelBox` derives from `labelBoxGeometry` (10px font, 130px max width, a 0.58 average-char-width ratio mirroring the base node style rule), so widening that ratio or the background padding is the tuning knob if labels still touch. It is **screen** space, so the cull re-runs on every pan/zoom through `applyGraphVisualState`, and a node whose geometry is unusable **fails open** (label kept) — silently hiding a label is worse than an overlap. The cull only ever removes from the `is-labeled` set: `is-selected`/`is-hovered`/`is-neighbor`/`is-search-match`/`is-dimmed` are untouched, so a node whose label is culled keeps its focus styling.
- **Theme changes repaint without relaying out**: `restyleGraphForTheme` replaces the whole stylesheet via `cy.style(buildGraphStyle())` and re-runs `applyGraphVisualState`; it never touches elements, positions, selection, or the viewport, and it must stay that way — a relayout on theme toggle would throw away a hand-arranged view. Two ordering facts in `graph-style.ts` are load-bearing and pinned by tests in `graph.test.ts`: `edge[?mutual]` sits between the base edge rule and `edge.is-highlighted-edge` so a highlight still wins, and the aggregate rules bracket the state classes (`node[?isAggregate]` before them, `node[?isAggregate].is-hovered` after) so the aggregate's own hover affordance wins the equal-specificity tie while `is-neighbor`/`is-selected` still override its base look. Cytoscape's `[?field]` selector matches on truthiness, so `mutual: false` deliberately falls through to the bezier base rule.
- **Rebuilds are debounced and layout runs are tokened**: a display-knob rebuild is a synchronous remount plus a relayout, so `scheduleDisplayRebuild` collapses a slider drag into one trailing rebuild *and* calls `stopActiveLayout()` immediately, killing the layout belonging to a position the user already moved past; `runLayout`'s `layoutRunID` bump is the backstop that discards a stale `layoutstop`. The URL and the slider readouts update synchronously on every `input` event and only the rebuild is debounced, so shareable state is never stale mid-drag. Every control-driven rebuild goes through `rebuildDisplayForControl` with `fitAfterLayout: false`, `preserveViewport: true`, `resetPositions: false`; `applyGraphElements` then captures the mounted positions before the remount and replays them through `seedDeterministicPositions`' keep map, so surviving nodes stay where they were and only newly introduced nodes (an aggregate, say) get seeded. A fetch-driven load is the opposite — fit and reset — because the graph itself changed.
- **Every `graph*.ts` change ships as a regenerated bundle**: `static_src/` is the source, `internal/web/static/app.js` is the committed artifact, and a change to one without the other is a broken commit — the page loads the bundle, so unbuilt TypeScript is a change no browser ever runs. `just web-build` regenerates it, `just web-check` regenerates it on the way through typecheck and Vitest, and `just ci` hashes the on-disk bundle, rebuilds, and byte-compares, so drift fails the gate rather than shipping. Note that the bundle legitimately still contains the string `g_hops` — it is the compiled `legacyHopsParamKey` constant — so "the retirement is done" is not something a grep over `app.js` can assert.
- **What is doc-only here**: `just ci` covers the stage order, degree recomputation, the aggregate rules' array positions, the label-cull geometry, the asset load order, and `layoutOptionsForSpread`'s fall back to `cose` (`graph-controller-layout.test.ts`, "falls back to cose when fcose is absent"). It covers the one-hop contract at every layer it can reach without a renderer: the neighborhood and its composition with min-degree and collapse in `graph-controller-view.test.ts`, the mounted-element boundary and the refusal of tap/hover/select/keyboard events for excluded nodes plus the legacy-URL canonicalization (unrelated params and hash preserved, repeated keys removed) in `graph-controller.test.ts`, the absence of the Hops markup from the rendered template in `TestServer_GraphPageViewControlsMarkup` (`internal/web/server_pages_test.go`), and the absence of its stylesheet rules in `internal/web/static_css_test.go`. It does **not** cover the rendered result of any of it — including the vertical rhythm of `.graph-view-controls` now that the Hops block is gone. `separateIsolatedNodes` running only on the fallback path, the aggregate hover affordance reading as "click to expand", `text-background-opacity`, and whether a spread sweep or a theme toggle thrashes have no automated guard and are held by this document plus the QA pass recorded in the plan's session 7 — treat a change in those areas as needing a browser, not just a green suite.
