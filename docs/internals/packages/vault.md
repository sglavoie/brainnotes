# internal/vault

[Back to the architecture map](../architecture.md).

- `internal/vault` — `Vault` is a root path + config. `Walk` skips hidden dirs, configured ignores, and the templates dir automatically (template files contain unrendered placeholders that are not valid YAML, so they must never be walked). `Notes()` loads everything in memory — fine for the documented working size (~300 notes); switch to streaming `Walk` if scaling beyond a few thousand. `Notes()` is strict: one note whose frontmatter fails to parse (a `*ParseError`) fails the whole load, which is what mutating commands want. `NotesLenient()` is the read-only variant: it returns such notes as `SkippedNote`s instead, still failing on any I/O or walk error; `internal/cli`'s `loadReadableNotes` warns about them on stderr and `bn lint` reports them as `parse` violations. `WalkExclusion` is that pruning rule stated as a predicate, so a writer choosing a destination can refuse the locations `Walk` would never visit — a note created under an ignored, hidden, or template path exists on disk yet is invisible to every query. It is the rule **plus a fold**: both configured exclusions are compared case-insensitively, which makes it deliberately stricter than `Walk` on a case-sensitive filesystem, because `Walk` prunes by the name it finds on disk and a create of `archive/Old.md` against an ignored `Archive/` lands inside that real directory on a case-insensitive one. The asymmetry and its price are stated on the function. `ResolveByTitle` does case-insensitive stem lookup and returns an ambiguity error listing all candidates. It also owns locking and `FileTxn`, whose write contract — including the fsynced recovery intent under `<vault>/.bnotes/txn/` that lets a *killed* process's transaction be finished on the next open or the next mutation — is in `docs/internals/locking.md`. `Vault.Open` runs that recovery pass best-effort and ignores its result so read-only commands are never refused; `acquirePathLocks` runs the same pass and returns its error, so every write fails closed. `SyncDir` is exported from here for the one package that keeps durable state outside the vault tree (`internal/vaultgit`, under `.git`) rather than duplicating its per-platform build tags.
