# internal/web/static_src/css

[Back to the architecture map](../architecture.md).

- `internal/web/static_src/css` + `internal/web/cssbuild` — the stylesheet's source parts and the builder that concatenates them, in the order `index.css` lists, into the committed `internal/web/static/app.css`. The split exists for the reason the TypeScript one does: one 6,800-line stylesheet has no section boundary anything can enforce, so a graph rule lands in the Markdown block and nothing notices. **It is a concatenation, not a bundle**, and that is the whole design: the parts are the source of record, and a CSS bundler re-serializes them — esbuild drops every explanatory comment and rewrites `[aria-busy='true']` to `[aria-busy=true]`, both semantics-preserving and both leaving an artifact that no longer reads as what was written (six `internal/web` CSS contract tests assert those selectors against the generated file). Byte-for-byte concatenation is also why the drift check needs no normalization and no toolchain: `cssbuild.Build` rebuilds in memory and `TestCommittedStylesheetMatchesSources` compares, so `go test ./...` catches a stale stylesheet where Node is absent, and `just ci` needs no CSS step of its own. **The manifest order is the cascade** — moving an import moves the rules it names — so `tokens.css` stays first (every part reads its custom properties), `responsive.css` stays last (its width-scoped blocks only override the components they narrow by following them), and `TestCascadeAnchorsKeepTheirPositions` pins both ends, since a reordered import is a silent visual regression rather than a build failure. `focus.css` sits between the two facet parts because that is where the shared focus ring was written in the cascade, not because it belongs to facets. The manifest is parsed strictly and a part file no import names is an error: a dropped import still builds a valid stylesheet, so its only symptom is a page rendering unstyled. `WriteBundle` is the one write, it targets a tracked build artifact inside the caller's own checkout rather than anything in a vault (hence its `//bn:direct-write` marker), and it skips an identical file so `bn serve` does not touch the artifact's mtime on every start.
