# Architecture internals

Companion to `CLAUDE.md`; read before adding a package or changing responsibilities between existing ones.

Layered packages, each with a focused responsibility. Commands compose primitives from the lower layers — keep the boundaries clean rather than reaching across them.

- `cmd/bn/main.go` — thin entrypoint, delegates to `internal/cli.Execute`.
- `internal/cli` — Cobra command tree. `root.go` wires persistent flags and uses `PersistentPreRunE` to load config into the command context (extract with `ConfigFromContext`). Each subcommand lives in its own file; `related.go` owns ranking/output/interactive selection, `related_feedback.go` owns explicit sidecar writes, and `context.go` owns deterministic bundle export plus optional agent execution. `target_resolution.go` is the shared NFC-aware single-note resolver for links/backlinks/related/context. `recall_corpus.go` is the one place a recall-reading command pins its clock (`recallNow`, threaded into both `recall.WithClock` and `RankOptions.Now`), wraps the state store as the read-only `recall.RecallSignalSource`, and extracts the corpus/graph/ranker triple, so `related`, `context`, and `find --sort relevance` cannot build different corpora from the same vault; `find_sort.go` is the caller-side ordering layer for `--sort`/`--relative-to`, since `queryexpr` parses a `SortSpec` but never ranks. `notes.go` centralizes multi-note positional handling: it resolves paths from args, globs, or stdin (`-` triggers stdin; `-0` toggles NUL separation) and enforces in-vault containment. `findflags.go` owns the shared filter surface and is the **single execution path** for it: `register` binds the find flags plus `--query`/`-q` and `--view`, `compile(env)` folds all three sources into one `*queryexpr.Plan` whose `Expr` is their AND, and `selectNotes` builds the link graph only when `needsGraph(plan)` says so and then runs one `Evaluator.Evaluate`. Every flag-scoped command routes through it — `find`, `search`, `graph`, `lint`, and the four scoped mutators via `collectReplaceCandidates` — so a filter cannot mean one thing to `bn find` and another to `bn replace`. The two text sources are compiled separately rather than concatenated, because a `*queryexpr.ParseError` renders carets against the source it was parsed from. `queryFlagNames` in `replace.go` must list every one of these flags, `--query` and `--view` included, or the note-args/find-flags mutual-exclusion check silently stops firing; `RenderError` in `root.go` is the one place an error is printed and the one place that upgrades a `*ParseError` from its one-line `Error` to the caret block `Render` draws. `views.go` is the read-only `bn views`/`show`/`check` tree: all three go through one `resolveConfigViews` helper that builds an `Env` from `config` alone, so listing views never walks the vault and never builds a graph, and every one of them honours the disabled-not-dropped contract — `views` prints a `STATUS` column, `show` returns the view's own error so `RenderError` draws its carets, and `check` exits non-zero so it is usable as a config health gate.
- `internal/config` — TOML loader for the single vault-local `brainnotes.toml`. That file is the vault-root marker, so resolving the vault root and locating the config are the same operation: `--vault` → `$BNOTES_VAULT` → an upward search from the working directory, each of which requires the directory to actually contain `brainnotes.toml`. `LoadOptions` injects the flag, working directory, and environment lookup so precedence is testable without touching real process state. `Vault`, `SourcePath`, and `VaultOrigin` are runtime-only fields (`toml:"-"`); there is no `vault` key. `DefaultIgnore` (`.git`, `.obsidian`, `Attachments`, `Archive`, `Trash`) is always merged in. `[related]` controls only the metadata property list; fixed ranking weights are not configuration. Top-level `[agent]` is a literal argv plus timeout shared by context research and, when no legacy cockpit override is set, daily review. Saved views live in a `[[views]]` **array of tables** decoded into `Config.Views []SavedView{Name, Query, Sort, RelativeTo, Limit, Description}` — an array rather than `[views.<name>]` tables because the list is ordered, and `bn views` and the web nav present views in file order. Validation of a view is deliberately **shape-only** (name pattern, case-insensitive uniqueness, non-empty query, `limit >= 0`): `config` is the bottom of the layering, so importing `internal/queryexpr` to check that `Query` parses would close a cycle, exactly like the documented `pins`/`noteops` edge. The load-bearing consequence is that a view whose expression rotted still loads — one stale view must never make a vault unopenable — and every layer above is required to render it as a **disabled entry carrying its parse error**, never dropped and never a 500. `queryexpr.ResolveViews` is the single place that resolution happens (see below), and `bn views check` is the user-facing answer. `patch_views.go` is the comment-preserving TOML patcher for that section: it reuses `splitConfigLines`/`joinConfigLines`/`diffLines`/`quoteTOMLString` from `patch.go` and adds the array-of-table header parser in its own file rather than widening `parseTableHeader`, which explicitly treats `[[` as "not a header". A view block runs from its `[[views]]` header to the next table header (so deletion cannot glue two sections together), a rename rewrites only the `name` line, and an upsert replaces the whole block — which is why `PatchResult.Diff` is a mandatory preview rather than a courtesy: `brainnotes.toml` is the vault-root marker and a mangled patch is a vault-wide failure.
- `internal/vault` — `Vault` is a root path + config. `Walk` skips hidden dirs, configured ignores, and the templates dir automatically (template files contain unrendered placeholders that are not valid YAML, so they must never be walked). `Notes()` loads everything in memory — fine for the documented working size (~300 notes); switch to streaming `Walk` if scaling beyond a few thousand. `WalkExclusion` is the same pruning rule stated as a predicate, so a writer choosing a destination can refuse the locations `Walk` would never visit — a note created under an ignored, hidden, or template path exists on disk yet is invisible to every query. `ResolveByTitle` does case-insensitive stem lookup and returns an ambiguity error listing all candidates.
- `internal/frontmatter` — parse/rewrite YAML frontmatter. `Map` preserves insertion order during parse but `Marshal` **always emits keys alphabetically sorted** — this is intentional and load-bearing for stable diffs. Values are Go-native types (string, int, float64, bool, time.Time, []any, map[string]any). Wikilink-typed properties are auto-wrapped in `[[ ]]` on write.
- `internal/wikilink` — Obsidian-style `[[Target#Heading|Alias]]` parsing and rewriting. **Code-block aware**: links inside fenced, indented, or inline code are masked out so rewrites never touch documentation samples or code snippets. Used by `rename` (rewrite all forms when title changes) and `move` (rewrite folder-prefixed forms only — bare `[[Title]]` links resolve by title alone in Obsidian and are deliberately left untouched).
- `internal/query` — composable `Predicate` functions over `*vault.Note` for the `find` command's frontmatter dimensions (tag/category/status/type/has/missing/folder/age/orphan), plus the path-aware wikilink graph reused by recall ranking. `And` is the identity-with-no-args combinator; queries with no flags match everything. The graph contract is no longer only orphan detection: `graph_metrics.go` derives `GraphMetrics` from a built `Graph` by inverting `Forward` into sorted out/in/both adjacency, and answers **bounded graph traversal** — `Degree` (the *undirected* distinct-neighbour count), undirected connected `Components`/`ComponentSize`, and `Distances`/`Distance` BFS under a `maxHops` bound where a negative bound means unbounded, plus `ShortestPath`, which computes distances *towards* the target and steps greedily to the smallest neighbour one closer, yielding the lexicographically smallest shortest path without enumerating paths. `filter_graph_ops.go` turns that into the six graph predicates `queryexpr` lowers onto (`LinksTo`, `LinkedFrom`, `Near`, `PathTo`, `Degree`, `ClusterSize`), each of which resolves its target **once at build time** into a key set or a reachable set, so a term costs one traversal per scan rather than one per note. Direction on `Near`/`PathTo` is anchored at the **candidate note**, not the target: `DirOut` means "the note reaches the target by its own outgoing links", implemented as one BFS out of the target along `dir.reverse()`. Every one of them ends in `Reachable(g, keys)`, the exported membership test, which is why the memoized `queryexpr` path runs literally these predicates rather than a reimplementation. Two keyspaces coexist and must not be confused: `GraphMetrics` takes a **note key** (`areas/foo`), while `Graph.OutDegree`/`InDegree` take a **title** — resolve through `Graph.KeyForNote` or `Graph.ResolveTarget` first. An isolated note is a component of size 1 with degree 0, so `cluster-size:1` and `degree=0` both mean "unlinked note"; membership is gated on `GraphMetrics.has` so a note absent from the graph never matches at all.
- `internal/queryexpr` — the vault query expression language: the surface syntax users type into `bn find`, the library query bar, and the graph filter, lexed and parsed into one shared AST (`And`/`Or`/`Not`/`Term`, precedence `not` > `and` > `or`, juxtaposition meaning AND). It is deliberately a sibling of `internal/query` rather than files inside it: `query` is imported by `recall`, `noteops`, `cockpit`, `web`, and `brief`, and typed comparison needs `config` and `schema`, so folding the language into `query` would widen that contract for every existing consumer. The dependency therefore runs one way — `queryexpr` may import `query`, `config`, `schema`, `frontmatter`, `vault`, `wikilink`, and `textnorm`, and **must never** import `recall`, `cli`, `web`, `noteops`, `properties`, or `cockpit`; `layering_test.go` parses the package's own imports and fails on a violation. `Expr.String()` re-renders canonical source and round-trips through `Parse`, so it is what a saved view prints and what the web layer normalizes an `expr=` parameter to; canonicalization is idempotent rather than byte-preserving, because atom text is NFC-normalized through `internal/textnorm` on the way in. Every failure is a `*ParseError` carrying the source, the byte span, a **rune-based** column, and did-you-mean candidates — `Render` draws a caret line padded by rune count, since accented text in a query is exactly what byte columns get wrong. `Compile` lowers a parsed `Expr` onto `internal/query` predicates through the reserved-field table in `fields.go`, and returns a `Plan` — the validated expression plus the caller-supplied `SortSpec` and `Limit`, which are *not* expression syntax. Compilation needs no link graph: `Plan.NeedsGraph` reports whether one is worth building (staying compatible with `findFlags.needsGraph`) and `Plan.Predicate` builds the closures against whatever `Env` the caller finally assembles, deriving `GraphMetrics` from the graph when a caller supplies only the graph. A plan whose `Env` lacks that state fails with a `*MissingStateError` rather than silently matching nothing. `Evaluator` runs a plan against a corpus; `NewMemoryEvaluator` scans an already-loaded `[]*vault.Note`, builds the graph lazily, and rejects an ordering it cannot honour instead of quietly ignoring it. `typed.go` compares a frontmatter property according to its **declared** `[frontmatter.properties]` type and nothing else — there is no key-name special-casing anywhere in it, and it reuses `schema.CheckScalar`/`schema.TryCoerce` for kind checking rather than re-deriving it, adding only literal parsing and the comparison operators on top. The declared type decides which operators are legal (`string`, `wikilink`, and `bool` define only `:`/`=`/`!=`; `date`, `datetime`, `int`, and `float` define ordering too; a list defines only `:`, meaning contains-any with each element parsed as its declared `items` kind), and ordering an unordered kind is a compile error naming the declaration rather than a silent miss. An **undeclared** key is still queryable, but through `prop:<name>` rather than bare — a bare unknown name has to stay an unknown-field error or did-you-mean has nothing to be wrong about — and there it falls back to the same stringify-and-fold comparison `Tag` and `Status` use, with ordering operators requiring the stored value to really be an `int`, a `float64`, or a `time.Time` and skipping the note when it is not. A property's `allowed` list is deliberately **not** enforced on queries: finding the notes that violate your own schema is the point. Relative literals (`today`, `now`, `+30d`, `"-7d"` — quoted, because a leading `-` lexes as negation) resolve against `Env.Now`, which is what makes a date query testable without depending on the day the suite runs. `graph_terms.go` holds the six fields that read link structure (`links-to`, `linked-from`, `near`, `path-to`, `degree`, `cluster-size`) and is merged into the reserved table by `withGraphFields`, because those fields need two things no other field does. They name a **note**, so a target can be spelled correctly and still refer to nothing: every target is resolved through `Graph.ResolveTarget` before its predicate is built, and an unresolvable one is a `*ParseError` with did-you-mean candidates rendered from `Graph.OriginalTitles` (never the folded `NoteKeysByTitle` keys, which are not copy-pasteable back into a query) — an empty result set would otherwise be indistinguishable from a correct empty result set. Resolution needs the graph, so it runs at compile time when `Env` already carries one and inside the builder otherwise, making the diagnostic later but never absent. And they are the only fields whose cost is a traversal: `near` and `path-to` are both reachability, so they share one BFS memo that lives for exactly one `Plan.Predicate` call, holds **unbounded** distance maps keyed by anchor and direction (so every hop bound is a filter over one traversal), and is consulted only while predicates are being built — never during the scan. The memo is deliberately not on `GraphMetrics`: that value is built once per command run or web snapshot and read by concurrent requests, so a cache hung off it would need a mutex on the hot path or would be a data race. Both traversal terms lower onto `query.Reachable`, the exported membership test `Near`/`PathTo`/`LinkedFrom` themselves end in. `flags.go` bridges the older flag surface: `queryexpr.FromFlags(query.Flags) (Expr, error)` lowers the flattened `bn find` flag set onto the same AST, preserving the asymmetric activation rules (`MinBacklinks > 0` activates, `MaxBacklinks >= 0` activates, because a minimum of 0 filters nothing while a maximum of 0 is the meaningful "nothing links here" filter). It is knowingly a **second** implementation of `query.FromFlags`, which stays exactly as it is: `internal/query` cannot import `internal/queryexpr` without a cycle, and `query.FromFlags` has eight callers with a test surface that predates this package. `flags_equivalence_test.go` is what makes the duplication acceptable and is the deliverable of the bridge — it runs the flag matrix through both paths against one fixture vault, rendering the expression to canonical text and recompiling it, and requires byte-identical sorted path lists (or agreement that the value is rejected). If that test ever becomes hard to keep green, that is the signal to merge the two packages and accept the `config` import, not to loosen the test. Two divergences are accepted and documented on `FromFlags`: error text differs, and a missing graph or root fails at `Plan.Predicate` with a `*MissingStateError` rather than at `FromFlags`, because that state arrives through `Env` rather than through `Flags`. `sort.go` holds `SortSpec{Key, Descending, RelativeTo}` and `ParseSort` over `path` (the default), `title`, `modified`, `created`, `backlinks`, `degree`, `pinned`, and `relevance`, accepting a direction as either a sign prefix (`-modified`) or a suffix (`modified:desc`) but never both. **`queryexpr` never ranks** — a `SortSpec` is a declarative spec and nothing more, which is what keeps the recall sidecar's read/write boundary out of a package whose job is compiling text; `ParseSort` never sets `RelativeTo`, since that names a note and binds to its own flag. `sortNotes` in the memory evaluator distinguishes an unknown key (a bad spec `ParseSort` would have rejected) from a valid key it does not order by (the caller's job), so a caller can tell which mistake it made. `views.go` is where a `config.SavedView` becomes runnable: `ResolveViews` returns one `View{Saved, Plan, Err}` per saved view, in file order, always — a query that no longer compiles comes back with its `*ParseError` on `Err` and a nil `Plan` instead of being omitted or raised, which is what makes "disabled, with its error" the default rendering everywhere. `RelativeTo` is read from its own config field rather than from the sort text, because `SortSpec.String()` deliberately drops it. `completion.go` is the editor-facing introspection surface — `Fields`/`IsReservedField` expose the reserved vocabulary with a one-line hint per name, `FieldsUsed` reports the fields a parsed expression names, and `CompletionAt(src, pos)` answers what is being typed at a caret. It is deliberately a **backwards scanner rather than a parse**, because the moments a completion is wanted (`tag:`, `near:[[Deep`) are exactly the moments the expression does not parse; it reuses the lexer's own `isWordRune` so a completion token can never disagree with the token the parser would cut. It reports syntax only — which field, which argument, which prefix, which byte span a candidate replaces, and whether the caret sits inside a quote or a `[[` — and never values, since sourcing those needs `properties` and the facets machinery that this package must not import. One rule is load-bearing and tested: an operator must be **adjacent** to the caret's token for a value position, so `tag:wi` completes values while `tag: ` (with a space) is a fresh field position.
- `internal/recall` — deterministic contextual retrieval with no persistent index. Extraction preserves exact note bodies/source spans while building NFC-normalized weighted title/heading/prose fields and configured metadata pairs. `BuildRanker` combines fixed text/graph/metadata/recall weights and returns stable reasons/mode filters. `BuildContextBundle` keeps the source body complete, admits ranked related excerpts under one selection shared by Markdown and JSON, and enforces the byte cap against both renderers. `Ranker.RankSelected` and `BuildCuratedContextBundle` are the explicit-selection pair: selection is authoritative, so caller order is preserved and recall dismissal/snooze suppression and mode eligibility never drop a chosen note. Every curated supporter contributes at least one exact excerpt — a supporter with no extractable body block is rejected rather than reduced to an identity — and curated `MaxBytes` is a starting budget rather than a cap: it grows only as far as the mandatory anchor body and one excerpt per supporter require, never past `MaxCuratedBundleBytes` (1 MiB). `StandardPurpose` owns the shared synthesis/contradictions/questions definitions so no caller can present different instructions under one purpose name. `StateStore` owns flock serialization for `<vault>/.bnotes/recall.json` and holds the sidecar path lock across every fresh read-modify-write; read-only queries stay lazy, explicit writes prune stale records, and corrupt/invalid/symlinked state fails closed.
- `internal/agent` — shared argv-only process runner. Callers own context timeouts; stdin/stdout remain byte-exact; diagnostics are bounded and sanitized. There is no shell, provider SDK, persistence, or implicit network behavior. `bn context --agent` sends its canonical Markdown preview, while the web daily-review path sends only its separately redacted review payload.
- `internal/template` — discovery and rendering for `bn new`. Template lookup is case-insensitive and tries `<name>`, `<name>.md`, `<name> Template.md`. Render helpers: `now`, `today`, `dateFormat`, `slug`, `title`, `lower`/`upper`, `default`, `env`, `wikilink`. The `.Vars` map holds repeatable `--var key=value` pairs.
- `internal/web/static_src` — strict TypeScript source for first-party browser behavior. `esbuild` bundles it into `internal/web/static/app.js`, which stays committed so Go builds and installs do not require Node. `internal/web/static/cytoscape.min.js` remains vendored and is not bundled.
- `internal/web/server.go` serves embedded static files by default, but accepts an injected static filesystem. `internal/cli/serve.go` uses a `sourceCheckoutRoot` value stamped via justfile `-ldflags` first, then current-directory checkout detection, and injects disk static assets after a successful web build so the current `bn serve` process sees freshly generated browser JavaScript.
- `internal/cockpit` — the shared Daily Fix Cockpit core. `BuildQueue` scans the vault and groups hygiene issues (frontmatter parse errors, schema violations, broken link targets, duplicate titles, orphans, dead ends, long-tail property values) plus opt-in advisory rules (`sensitive_content`, `missing_review_date`, `stale_status`, `wip_limit`, `hub_needs_synthesis`, `capture_backlog`) into a deterministic, content-addressed `Queue` of `Task`s, each advertising the `Action`s that can fix it. Advisory tasks are triage-only (no fix action, never mutate notes); `sensitive_content` surfaces only a redacted line/detector-category location and never the matched value. `StateStore` persists per-task workflow state (done/snoozed) in `<vault>/.bnotes/cockpit.json` and migrates readable records from the legacy `<vault>/.bnotes/review.json` on first load. `Fixer` plans and applies fixes through `internal/noteops`. `LimitDaily` caps the queue to `cockpit.daily_limit` for the daily view, and `BuildReviewContext` builds the deterministic, redacted snapshot shared by `bn doctor --review-context`, `GET /api/daily-review/context`, and the optional local `POST /api/daily-review/agent` (argv-only, stdin-fed, opt-in — no provider dependency). Both `bn doctor` (`internal/cli/doctor.go`) and the web cockpit APIs (`internal/web/cockpit_api.go`, `internal/web/cockpit_agent.go`) consume this one core so CLI and web stay identical.
- `internal/noteops` — the shared note-mutation layer used by both CLI commands and the web APIs. `preview.go` defines the canonical `NotePreview`/`PreviewChange` model that every mutating command's `--dry-run` and every web preview render through, so the two views can never drift. `capture.go` holds the quick-capture primitive behind `bn capture` and the web quick-capture box: `PreviewCapture`/`ApplyCapture` append one fixed-format `- YYYY-MM-DD HH:MM <text>` bullet to the configured inbox note under the configured heading, splicing bytes (never re-marshaling frontmatter) so every pre-existing byte survives — the write is strictly additive, so even the heading-absent path only appends a separator, the heading, and the bullet rather than collapsing trailing blank lines — bootstrapping the note inline when it is absent, and — uniquely among noteops writes — re-reading and re-planning up to 3 times on a `vault` transaction conflict before returning `CodeConflict`, which is safe only because an append is commutative. `capture_heading.go` owns the single line-oriented heading scanner and exports `CountSectionBullets` so `internal/cockpit` counts exactly the section the writer would append to; its `containsATXHeading` is what makes the synthesis draft's reserved `## Sources` heading detectable without matching fenced-code samples. `synthesis.go` is the create-only pair behind the synthesis workbench: `PlanSynthesisNote` resolves the destination, validates the draft, and returns the exact bytes plus every read-only expectation, and `ApplySynthesisNote` writes those exact bytes rather than rebuilding them, so what a user previewed is what lands. A synthesis plan always carries `ExpectMissing` — V1 creates new notes only and `ApplySynthesisNote` refuses any other expectation — and its `Requirements` pin every ordered source (and, when the caller supplies it, `brainnotes.toml`) through `FileTxn.Require`, so a source edited between preview and apply is a `CodeConflict` with no note and no journal entry. Plan-time verification through `vault.VerifyState` is a courtesy that refuses a doomed plan early; only the transaction's own recheck makes the write safe.
- `internal/properties` — the reusable property index behind the web workbench. `typed.go` defines `TypedValue`, the transport form a caller sends when it wants a value written under a declared kind. `value.go` classifies a frontmatter value into a discriminated `Value` (`kind`/`text`/`value`/`items`/`supported`); anything YAML can hold but frontmatter text cannot safely reproduce (null, mapping, nested list) becomes `KindUnsupported` with a label and no reproducible text. `index.go` walks notes once to build per-property coverage, observed kinds, distinct logical values, note rows, and `internal/schema` violation counts, counting each logical value at most once per note so repeated list items never inflate statistics. `infer.go` proposes a `[frontmatter.properties.<key>]` block only for an unconfigured property whose observed values unanimously support one kind, and never infers `required` or `allowed`. The package deliberately does not depend on `internal/web`.
- `internal/pins` — the shared pinned-list core behind `bn pin`/`bn unpin`, `bn find --pinned`, `query.Pinned()`, the `/pinned` page, and the web pin endpoints. `Classify` maps a raw `pinned` value onto `NotPinned`/`Ranked`/`Unranked`: only an absent key and the YAML boolean `false` are unpinned, so a hand-written `pinned: true` or `pinned: "high"` is a pin carrying no rank that sorts after every ranked pin. `List` orders a vault's pins and silently skips a note it cannot read, cannot parse, or that falls outside the root, so one hostile note cannot hide the whole list. `PlanAppend`/`PlanMove` return `Assignment`s only — the package never writes — and fall back to a whole-list renormalize (`Plan.Renormalized`) when the float gap between two ranks is exhausted; `midpoint` and `nextRank` stay unexported so no caller can bypass that fallback. It is a **leaf package**: it must not import `internal/noteops`, because `noteops` imports `internal/query` and `query` imports `pins`, so that edge would close a cycle. In `internal/web`, note-pin identifiers are `notePin*`/`pinnedNotes*` because `pinnedConfig`/`configPin` already mean *configuration* pinning there.
- `internal/index` — a persistent cache of note bytes keyed by the revision they were read at, so a repeated vault load pays a stat per note instead of a read per note. **It saves the read and not the parse**: every `Load` parses a fresh `*vault.Note` out of each walked note's bytes whether they were just read or served from the cache, so a warm load still runs `frontmatter.Parse` once per note. `BenchmarkDirectLoad`/`BenchmarkColdIndexLoad`/`BenchmarkWarmIndexLoad` time the three paths over a 500-note vault and `TestLoadCostsAreOneReadPerMissAndOneParsePerNote` counts what each performs — reads through the `WithReader` seam, parses through the unexported `Index.parseNote` field that exists for exactly that count. It is a **leaf package**: it may import `vault`, `config` and `frontmatter`, it consumes a `*vault.Vault` and produces `[]*vault.Note`, and it stops there — the same one-way contract `internal/properties` holds by deliberately not depending on `internal/web`. It must never import `query`, `queryexpr`, `properties`, `schema`, `noteops`, `cockpit` or `web`, all of which are consumers of the note slice it returns; `TestPackageLayering` pins that over non-test files, and `parity_test.go` reaches up into `queryexpr` on purpose to evaluate real queries against both load paths. `Load` runs `v.Walk(vault.WalkFilter{}, ...)` and nothing else, because `Walk` is the sole encoding of hidden-directory pruning, the ignore list, the templates directory, and symlink rejection — a hand-rolled `filepath.WalkDir` here would fork all four. Per file it stats, treats the cached entry as clean only when size *and* mtime match *and* that mtime is older than a **2s non-configurable `staleWindow`**, and otherwise re-reads and re-hashes; entries the walk did not visit are dropped, and `Result.Changed` reports whether note contents differ from the previous observation. The stale window is the package's sharpest edge: `vault.Note` carries a `SourceHash` precisely so a concurrent external edit is rejected rather than silently overwritten, but size+mtime cannot see an edit that lands inside one mtime tick while preserving byte length — which is exactly `sed -i s/draft/done/` on a filesystem with one-second mtime granularity. Every snapshot parses a **fresh `*vault.Note`** from the immutable cached `[]byte` rather than sharing a `Note`, because a `Note` is mutable and callers treat a returned snapshot as immutable. State lives in `<vault>/.bnotes/index/` and the locking contract is in `docs/internals/locking.md`. It **self-heals silently**, deliberately inverting `internal/recall`'s fail-closed state store: `recall.json` holds irrecoverable user intent, the index holds none — every byte is a pure function of the vault — so a missing, unreadable, non-regular, undecodable, wrong-version, wrong-root or internally inconsistent state file is discarded and rebuilt. Two hard rules follow: an index failure is **never** a request error (degrade to a direct load, log once per failure class per process), and disk-write failures are ignored entirely. A cached entry records `len(data)`, **not** the size the preceding `os.Stat` reported: the two differ only when a writer lands between the stat and the read, and taking the stat's value there both writes an entry `validEntry` rejects and can pair the new file's size and mtime with the old file's bytes — the stale read `clean` exists to prevent. Its only production caller is `internal/web`'s `noteSource` (`internal/web/state.go`): `newVaultState` defaults to `indexNoteSource` and falls back to `directNoteSource` if the index cannot even be constructed, the index reads through a reader that keeps `internal/web`'s bounded-read and quarantine rules, and a note quarantined *after* it was cached is re-checked at the source because a cache-served entry is never read. A test that injects a `noteLoader` gets the direct path by construction, since the index reads bytes itself and would silently ignore the loader. `bn index --status` / `--rebuild` (`internal/cli/index.go`, `index.Stat`, `Index.Reset`) is the whole user-facing surface, and `--status` never rebuilds.
