# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`bn` (Brain Notes) is a small Go CLI for editing and querying a plain-Markdown notes vault. It targets fast, vault-aware operations (frontmatter queries, wikilink-aware rename/move, templated note creation) that complement an editor rather than replace one. The README is the canonical user-facing spec — keep behavior aligned with it when changing commands.

## Common commands

The repo uses `just` for development tasks (see `justfile`):

- `just build` — build the `bn` binary in the repo root via `go build -o bn ./cmd/bn`.
- `just install` — `go install ./cmd/bn` (puts `bn` in `$GOPATH/bin`).
- `just test` — `go test ./...`.
- `npm ci` — install pinned frontend tooling before changing TypeScript source or running frontend checks.
- `just web-build` — bundle `internal/web/static_src/main.ts` into committed `internal/web/static/app.js`.
- `just web-check` — run frontend typecheck, Vitest/jsdom tests, and the browser bundle build.
- `just lint` — fails on `gofmt -l .` output, runs `go vet ./...`, then runs `just web-check`.
- `just ci` — the full validation envelope: `gofmt -l` check, `go vet ./...`, `go test ./...`, frontend typecheck + Vitest, the browser bundle build, and a check that the committed `internal/web/static/app.js` has no drift. Run this before declaring work complete (`scripts/health.py` runs exactly this).
- `just fmt` — `gofmt -w .`.
- `bn serve` — local `just build`/`just install` binaries remember this checkout path, rebuild web assets here before serving, and serve static assets from `internal/web/static` on disk. The serve-time build prefers the native `node_modules/esbuild/bin/esbuild` binary to avoid requiring `node`/`npm` when dependencies are already installed; unstamped binaries fall back to current-directory checkout detection, then embedded assets.

Run a single test: `go test ./internal/cli -run TestFind_TagFilter` (standard Go test selectors). Integration tests in `internal/cli/integration_test.go` use golden files under `internal/cli/testdata/`.

Go module is `github.com/sglavoie/sglavoie_brainnotes` (note: the binary is published as `github.com/sglavoie/brainnotes/cmd/bn` per the README, but the local module path differs — keep imports using the local module path).

## Architecture

Layered packages, each with a focused responsibility. Commands compose primitives from the lower layers — keep the boundaries clean rather than reaching across them.

- `cmd/bn/main.go` — thin entrypoint, delegates to `internal/cli.Execute`.
- `internal/cli` — Cobra command tree. `root.go` wires persistent flags and uses `PersistentPreRunE` to load config into the command context (extract with `ConfigFromContext`). Each subcommand lives in its own file; `related.go` owns ranking/output/interactive selection, `related_feedback.go` owns explicit sidecar writes, and `context.go` owns deterministic bundle export plus optional agent execution. `target_resolution.go` is the shared NFC-aware single-note resolver for links/backlinks/related/context. `notes.go` centralizes multi-note positional handling: it resolves paths from args, globs, or stdin (`-` triggers stdin; `-0` toggles NUL separation) and enforces in-vault containment.
- `internal/config` — TOML loader for the single vault-local `brainnotes.toml`. That file is the vault-root marker, so resolving the vault root and locating the config are the same operation: `--vault` → `$BNOTES_VAULT` → an upward search from the working directory, each of which requires the directory to actually contain `brainnotes.toml`. `LoadOptions` injects the flag, working directory, and environment lookup so precedence is testable without touching real process state. `Vault`, `SourcePath`, and `VaultOrigin` are runtime-only fields (`toml:"-"`); there is no `vault` key. `DefaultIgnore` (`.git`, `.obsidian`, `Attachments`, `Archive`, `Trash`) is always merged in. `[related]` controls only the metadata property list; fixed ranking weights are not configuration. Top-level `[agent]` is a literal argv plus timeout shared by context research and, when no legacy cockpit override is set, daily review.
- `internal/vault` — `Vault` is a root path + config. `Walk` skips hidden dirs, configured ignores, and the templates dir automatically (template files contain unrendered placeholders that are not valid YAML, so they must never be walked). `Notes()` loads everything in memory — fine for the documented working size (~300 notes); switch to streaming `Walk` if scaling beyond a few thousand. `ResolveByTitle` does case-insensitive stem lookup and returns an ambiguity error listing all candidates.
- `internal/frontmatter` — parse/rewrite YAML frontmatter. `Map` preserves insertion order during parse but `Marshal` **always emits keys alphabetically sorted** — this is intentional and load-bearing for stable diffs. Values are Go-native types (string, int, float64, bool, time.Time, []any, map[string]any). Wikilink-typed properties are auto-wrapped in `[[ ]]` on write.
- `internal/wikilink` — Obsidian-style `[[Target#Heading|Alias]]` parsing and rewriting. **Code-block aware**: links inside fenced, indented, or inline code are masked out so rewrites never touch documentation samples or code snippets. Used by `rename` (rewrite all forms when title changes) and `move` (rewrite folder-prefixed forms only — bare `[[Title]]` links resolve by title alone in Obsidian and are deliberately left untouched).
- `internal/query` — composable `Predicate` functions over `*vault.Note` for the `find` command's frontmatter dimensions (tag/category/status/type/has/missing/folder/age/orphan), plus the path-aware wikilink graph reused by recall ranking. `And` is the identity-with-no-args combinator; queries with no flags match everything.
- `internal/recall` — deterministic contextual retrieval with no persistent index. Extraction preserves exact note bodies/source spans while building NFC-normalized weighted title/heading/prose fields and configured metadata pairs. `BuildRanker` combines fixed text/graph/metadata/recall weights and returns stable reasons/mode filters. `BuildContextBundle` keeps the source body complete, admits ranked related excerpts under one selection shared by Markdown and JSON, and enforces the byte cap against both renderers. `StateStore` lazily reads and atomically writes `<vault>/.bnotes/recall.json`; read-only queries ignore stale records, explicit writes prune them, and corrupt/invalid/symlinked state fails closed.
- `internal/agent` — shared argv-only process runner. Callers own context timeouts; stdin/stdout remain byte-exact; diagnostics are bounded and sanitized. There is no shell, provider SDK, persistence, or implicit network behavior. `bn context --agent` sends its canonical Markdown preview, while the web daily-review path sends only its separately redacted review payload.
- `internal/template` — discovery and rendering for `bn new`. Template lookup is case-insensitive and tries `<name>`, `<name>.md`, `<name> Template.md`. Render helpers: `now`, `today`, `dateFormat`, `slug`, `title`, `lower`/`upper`, `default`, `env`, `wikilink`. The `.Vars` map holds repeatable `--var key=value` pairs.
- `internal/web/static_src` — strict TypeScript source for first-party browser behavior. `esbuild` bundles it into `internal/web/static/app.js`, which stays committed so Go builds and installs do not require Node. `internal/web/static/cytoscape.min.js` remains vendored and is not bundled.
- `internal/web/server.go` serves embedded static files by default, but accepts an injected static filesystem. `internal/cli/serve.go` uses a `sourceCheckoutRoot` value stamped via justfile `-ldflags` first, then current-directory checkout detection, and injects disk static assets after a successful web build so the current `bn serve` process sees freshly generated browser JavaScript.
- `internal/cockpit` — the shared Daily Fix Cockpit core. `BuildQueue` scans the vault and groups hygiene issues (frontmatter parse errors, schema violations, broken link targets, duplicate titles, orphans, dead ends, long-tail property values) plus opt-in advisory rules (`sensitive_content`, `missing_review_date`, `stale_status`, `wip_limit`, `hub_needs_synthesis`) into a deterministic, content-addressed `Queue` of `Task`s, each advertising the `Action`s that can fix it. Advisory tasks are triage-only (no fix action, never mutate notes); `sensitive_content` surfaces only a redacted line/detector-category location and never the matched value. `StateStore` persists per-task workflow state (done/snoozed) in `<vault>/.bnotes/cockpit.json` and migrates readable records from the legacy `<vault>/.bnotes/review.json` on first load. `Fixer` plans and applies fixes through `internal/noteops`. `LimitDaily` caps the queue to `cockpit.daily_limit` for the daily view, and `BuildReviewContext` builds the deterministic, redacted snapshot shared by `bn doctor --review-context`, `GET /api/daily-review/context`, and the optional local `POST /api/daily-review/agent` (argv-only, stdin-fed, opt-in — no provider dependency). Both `bn doctor` (`internal/cli/doctor.go`) and the web cockpit APIs (`internal/web/cockpit_api.go`, `internal/web/cockpit_agent.go`) consume this one core so CLI and web stay identical.
- `internal/noteops` — the shared note-mutation layer used by both CLI commands and the web APIs. `preview.go` defines the canonical `NotePreview`/`PreviewChange` model that every mutating command's `--dry-run` and every web preview render through, so the two views can never drift.
- `internal/properties` — the reusable property index behind the web workbench. `typed.go` defines `TypedValue`, the transport form a caller sends when it wants a value written under a declared kind. `value.go` classifies a frontmatter value into a discriminated `Value` (`kind`/`text`/`value`/`items`/`supported`); anything YAML can hold but frontmatter text cannot safely reproduce (null, mapping, nested list) becomes `KindUnsupported` with a label and no reproducible text. `index.go` walks notes once to build per-property coverage, observed kinds, distinct logical values, note rows, and `internal/schema` violation counts, counting each logical value at most once per note so repeated list items never inflate statistics. `infer.go` proposes a `[frontmatter.properties.<key>]` block only for an unconfigured property whose observed values unanimously support one kind, and never infers `required` or `allowed`. The package deliberately does not depend on `internal/web`.

## Implementation notes

- **Atomicity model**: file rewrites use temp-file + rename per file. There is no cross-file transaction — if `bn rename` or `bn move` errors mid-apply, prior writes stand. Mention this caveat in user-facing messages when relevant; rely on `git diff` for recovery.
- **Property semantics are config-driven** through one unified model: each `[frontmatter.properties.<name>]` section declares `type` (`string`/`wikilink`/`date`/`datetime`/`int`/`float`/`bool`/`list`), `items` (required for lists, naming the element kind — lists do not nest), optional `required`, and an optional `allowed` allow-list. There are no implicit runtime defaults, so the starter config spells out `categories`, `tags`, `topics`, `org`, `type`, `parent`, and `area`. `bn set k=a,b,c` splits on comma only for a property declared `type = "list"`, and auto-`[[ ]]` wrapping happens only for a `wikilink` type or a list with `items = "wikilink"`. Undeclared properties remain legal and are left alone by lint/repair. Tests rely on this — when adding new property semantics, extend `PropertyDefinition` rather than hard-coding key names.
- **Type coercion in `bn set`**: `true`/`false` → bool, integer → int, `YYYY-MM-DD` → date, else string. `--type date|int|bool|raw` forces a type.
- **Stdin convention**: `-` as the sole note arg means "read paths from stdin". For `bn unset` with multiple notes, use `--` to separate notes from property names. `-0` enables NUL-separated I/O end-to-end (paths in *and* paths out from `bn find`).
- **`PersistentPreRunE` skips config loading** for `completion`, `help`, and `init` so they remain usable outside a vault. `config` deliberately does *not* skip: it reports the resolved vault, so it needs the load to have happened.
- **Recall read/write boundary**: ordinary `bn related`, every `bn context` form, and `bn context --agent` never write recall state, the undo journal, or Markdown. Only successful `related -i` selection and `related feedback` write `<vault>/.bnotes/recall.json`; that sidecar is runtime state and is not recoverable through `bn undo`.
- **Context privacy boundary**: a context packet intentionally contains the complete source body plus selected exact excerpts. `--agent` receives exactly the inspectable Markdown bytes and prints stdout verbatim; the configured executable may transmit them, but `bn` itself adds no provider or network client. Do not reuse the web daily-review claim that bodies are redacted—the two agent inputs are intentionally different.
- **Context selection invariant**: Markdown and JSON must select the same related notes and source spans even though JSON escaping can be larger. Budget candidate changes against both serializers, never truncate the source body, and keep all excerpts tied to exact `Document.Blocks` locations.
- **Recall state recovery**: missing state is a valid empty read and is created lazily; missing-note records and expired snoozes remain untouched by reads and are pruned on the next explicit write. Never auto-repair or overwrite corrupt, unsupported-version, invalid-record, or symlinked state.
- Frontmatter rewrites must round-trip cleanly — preserve `Body` verbatim and only rewrite the frontmatter region. Tests under `internal/frontmatter/testdata` and `internal/cli/testdata` (golden files) catch regressions here.
- **`--dry-run` output has one canonical format** across every mutating command (`set`/`unset`/`replace`/`repair`/`relink`/`rename`/`move`). Each changed file is rendered by `internal/noteops`'s `RenderNotePreview` (`internal/noteops/preview.go`): a `--- <relpath>` header, then one line per change — `path: <old> -> <new>` for a rename/move, `frontmatter[<key>]: <old> -> <new>` for a property change, and `body:<line>: <old> -> <new>` for a body line. The same `NotePreview` model backs the web preview APIs, so CLI dry-run and web previews cannot drift. Preview-before-apply is mandatory for cockpit file changes: the web `/api/fixes/apply` requires a one-use `preview_id` from `/api/fixes/preview`, and bulk note actions require `/api/notes/bulk/preview` first.
- **Property intelligence cache**: `internal/web`'s `vaultState` caches one `*properties.Index` keyed on the snapshot serial plus the configuration generation, so a note reload or a `brainnotes.toml` reload rebuilds it and nothing else does. The cached index is shared and must stay immutable — `properties.Build` copies what it needs from notes and never mutates its inputs.
- **Property workbench save model**: `/api/properties/value` is the only unpreviewed property write, and it is deliberately narrow — one note, one property, either a whole-value replacement or a single list addition, gated on the caller echoing the note's current hash. Everything else (unset, list removal, multi-note changes, bulk value replacement, property rename, repair, and every schema edit) must go through `/api/properties/preview` then `/api/properties/apply`. Property receipts carry the configuration generation as well as the note hashes, so a `brainnotes.toml` change invalidates outstanding note receipts rather than letting a plan built against old declarations apply. A fatal blocker (`parse_error`, `not_found`, `key_conflict`, `config_conflict`) suppresses the receipt entirely so the whole selection is refused; `repair_skip` is advisory and leaves the receipt intact. When adding a property action, decide which side of this line it falls on rather than adding a third path.
- **Body diffs in `rename` / `move` dry-run** run the whole-body rewrite first and then diff line-by-line. Per-line rewriting would break `wikilink.Parse`'s code-fence masking, because a fence opener on one line is invisible to the next line's parse — the dry-run would report phantom changes for masked links that the apply path (which uses whole-body rewrite) correctly leaves alone.
